# 实验报告生成

## 固定约定

- 默认使用 `assets/template.docx`（用户最新上传的8行版本，过程区仅1行）。用户另给模板时优先使用新模板。只填五个正文区域，保留封面、课程名称、姓名、学号、班级、实验编号、项目名、时间、地点、环境、评分、学习态度、安全清洁、教师批阅原样，包括空白。
- 保持页面大小、页边距、固定栏字号、表格宽度、边框和固定区域行高。实验正文首页必须包含实验信息、目的、原理；过程可占多页；结果分析、小结、学习态度、安全清洁、教师批阅必须在同一个末页。封面和填写要求页保留，不计为实验正文首页。
- 除实验小结为150—200字外，不设统一字数页数；固定区域装不下时先精简，详细推导、测试记录移至过程，不能缩小字号、裁切正文或把末页拆开。
- 根据课程和每项任务动态选择过程结构。不要给无代码实验硬套代码章节。
- 统一使用“实验结果”作为结果说明标签，不使用“预期结果”。实验视为已完成：结果区一律写**结果分析**，用陈述句描述本次实验实际观察到的现象、数据与结论，可填写合理的实测数值（丢包率、时延、寄存器值等），禁止使用“若…则…可能…”的条件预测句式，禁止“以…为准”“依据…记录填写”“仅为示例”“待填写”等提示化表述。
- **所有实验的每个任务都必须有结果截图占位**，例如 `【截图：任务1_运行结果.png】`。在占位文字上添加真正的 Word 批注，说明软件、操作路径、输入、断点/观察位置、应截区域、保存名。不要生成假运行截图。指导书写“代码：（不要截图）”仅指**代码本身以 code 块文本呈现**，不代表运行结果可以不用截图——程序运行结果、命令输出、仿真现象等仍须按截图占位处理。
- 简单题报告放完整代码；较大项目放关键代码和解释，目录另附完整源码。报告片段与交付源码必须一致。
- 每个实验一个Word文件，按实验、任务分别建目录，逐任务提供完成的代码、配置、数据、原生项目等必要文件。多个实验附总ZIP，不合并Word。单实验有附属文件也附ZIP。
- 尽量提供软件可直接打开的原生文件，不能把文本改扩展名冒充工程。无法生成或验证时，在交付说明中明确限制并提供可用替代品。

## 正文排版

- 五个可编辑区域使用明确的字体与段落设置，禁止继承空白占位段落的双倍行距或字号。固定栏目标题保持原样。
- 正文中文宋体小四12磅，英文数字Times New Roman 12磅；1.5倍行距；段前段后0磅；首行缩进2字符、两端对齐。
- 任务标题用heading块，小四加粗、左对齐、不缩进并与下一段同页。小标题用label块；短说明可接写并仅加粗标签，长说明另起段。不得用空行拉开间距。
- 简单命令用command块：Consolas 12磅、单倍行距、左缩进2字符（24磅），多行命令每行对齐；长代码用code块：Consolas 10磅、单倍行距、左缩进2字符（24磅）、保留代码自身逻辑缩进；中文注释宋体。
- 每个任务的结果截图占位独立居中并保留真实批注；插入真实图片后在下方添加连续编号图注。无任何截图占位的报告视为不合格。
- 首末页容量不足先压缩文字并将详情移入过程；区分原模板兼容性问题与新正文格式错误，不能把未设置正文样式造成的溢页归因于环境。

## 报告语言

- 以学生报告正文直接描述实验对象、操作、原理和结果。不要把写作策略或生成指令放入正文，如“按指导书顺序完成”“本任务对应指导书填空”“便于逐项对应题目”。遵循指导书是生成规则，无需在正文声明。
- 用具体内容替代空泛提示，例如“采用持续发送、指定次数和指定数据长度三种设置，比较回复与丢包统计”。删除重复要求、无关交付说明和自我解释。
- **题目内容保持原实验指导书原文不变**：任务标题与要求文字一律逐字沿用指导书，只按本技能的格式排版（heading 块、code 块等），禁止改写、概括、合并、删减或调整题目顺序；题号统一 renumber 为连续序号 1. 2. 3. 4. ……（原题号缺号或乱序时按出现顺序重新编号，如原 1、2、4 依次改为 1. 2. 3.），不得使用“任务1”“任务二”等其他编号形式。
- 正文禁止要求腔表述：不出现“教师指定”“按教师分配”“老师要求”“按指导书要求”等字样，把要求改写为直接的操作陈述，例如不说“优先使用教师指定的跨网段地址”，而写“选取跨网段主机 1.1.1.1 作为探测目标”。
- 正文禁止指向外部文件的表述：不出现“见附件”“见附属文件”“详见…”等，关键配置、完整代码或数据直接写入正文。
- 正文禁止提示信息：不出现“以当前输出为准”“依据实验机记录填写”“仅为语法示例”“应以当前版本支持的命令为准”“只有允许访问时使用”等，直接给出本次实验采用的地址、命令和实际记录。

## 工作流程

1. 读取所有实验内容，提取实验分界、课程、任务编号、输入输出、软件版本、提交格式、思考题。重复引用同一文件去重；相同文件名但不同目录不得混淆。信息可合理推断时直接继续，只有影响正确性且无法推断的关键缺项才提问。
2. 使用可用的 documents 技能，先渲染模板作为基线。读取 `references/template-and-content.md`。不要把已完成报告的旧课程、日期、题目或运行数据当作新实验事实。
3. 逐任务完成可交付文件，执行可用且安全的编译、语法或运行检查。8086与现代x86不能混用；专用设备无法验证要说明。记录实测和推导的来源。
4. 生成五区正文。实验目的优先直接沿用指导书原文及编号。实验原理以指导书原理为基础，结合任务补充概念、公式、参数、工作机制，在固定区域容量内充分填写；超长时保留核心原理，将详细推导和参数解释移入过程，不缩小字号。实验内容及过程优先逐字沿用指导书的任务标题和要求原文，题号按出现顺序统一 renumber 为 1. 2. 3. 4. ……，在此基础上补充必要分析、操作和判读；思考题、填空与记录表逐项回应。结果说明统一标“实验结果”，按已完成实验的结果分析来写：陈述本次实验实际观察到的现象、实测数据与结论，允许填写合理的实测数值，但不用条件句预测结果、不留“待填写”空子。实验小结为150—200字，结合本实验的方法、关键点与改进方向，避免虚构经历。
5. 按 `references/template-and-content.md` 的JSON格式准备内容，调用 `python scripts/fill_report.py 内容.json 报告.docx [--template 模板.docx]`。脚本按标题定位区域、保留标题及其评分文字、填入段落并添加批注。不要用单元格整体赋值破坏标题格式。
6. 将全部实验任务连续写入唯一的“实验内容及过程”单元格，允许表格行跨页，随内容自动增页。禁止按任务复制表格行、禁止设置cantSplit或手动强制每任务另页。process_pages仅作为兼容输入分组，写入前展平，不表示物理分页。旧模板中若有额外空白续页行，将其移除并合并到一个过程单元格。
7. 渲染最终Word，检查每页PNG与PDF文本页码。确认首页三部分同页、末页五部分同页、无文字溢出/空白多余页、标题评分未损坏、代码无截断。调用 `python scripts/check_layout.py 模板.docx 报告.docx --pdf 已渲染报告.pdf` 检查固定XML和栏目同页；仍需目视确认正文未跨出目标页及末尾签名日期未溢出。检查批注锚点、关系和正文一致。基线模板在当前渲染器就已分页异常时，先排查字体和渲染兼容性；不能擅改模板或声称分页合格。不能消除时明确告诉用户，保留原文件并说明需在Word/WPS复核的具体位置。
8. 保存交付文件，按当前 Library 技能保存报告及ZIP。ZIP排除临时内容JSON、测试产物和渲染缓存，保留运行所需文件。最终简短说明交付内容及尚未验证的原生格式。

## 内容组织

| 类型 | 各任务过程 |
|---|---|
| 编程 | 要求、思路、代码、关键解释、运行调试步骤、实验结果及判读 |
| 软件操作 | 要求、步骤、参数设置、截图占位及批注、操作说明 |
| 电路硬件 | 设计分析、连接搭建、配置、测试条件与记录、实验结果及现象判读 |
| 综合 | 对每项任务分别选择上述结构，保持题号可追溯 |

## 交付目录

`实验编号_实验名称/实验报告.docx`，以及 `任务01_名称/`、`任务02_名称/` 等。任务目录存完整源文件及必要依赖、数据和项目文件；顶层 `交付说明.txt` 列软件版本、打开/运行方法、每个任务的入口、检查结果和未验证项。不要只交付代码截图、报告中的代码或空目录。
